# تشخیص خطای Failed to fetch در Search Console

**تاریخ:** ۱۵ شهریور ۱۴۰۵  
**منبع:** URL Inspection → More Info → JavaScript console messages

## پیام‌های ثبت‌شده

```
Log    [LiteSpeed] Start Lazy Load
       https://qpedia.ir/:179

Error  Uncaught (in promise) TypeError: Failed to fetch
       https://qpedia.ir/:178:9608
```

## 🔴 یافتهٔ اصلی: سرور جواب نمی‌دهد

هنگام بررسی، هر دو درخواست زیر **خطای ۵۲۲ کلادفلر** برگرداندند:

| آدرس | نتیجه |
|---|---|
| `https://qpedia.ir/` | ❌ 522 Connection timed out |
| `https://qpedia.ir/wp-json/` | ❌ 522 Connection timed out |

**خطای ۵۲۲ یعنی:** کلادفلر به سرور شما وصل شد، اما سرور در مهلت
مقرر جواب نداد. یعنی مشکل از **هاست** است، نه از کلادفلر.

این دقیقاً همان چیزی است که `Failed to fetch` را می‌سازد: جاوااسکریپت
درخواستی می‌فرستد، سرور جواب نمی‌دهد، درخواست تایم‌اوت می‌شود.

## تحلیل خطا

### چرا `Failed to fetch` مهم است؟

این خطا یعنی یک درخواست شبکه‌ای **کاملاً شکست خورده** — نه اینکه
جواب اشتباه گرفته باشد. سه علت ممکن دارد:

1. **سرور جواب نداد** (تایم‌اوت) ← ✅ تأییدشده در این مورد
2. مسدود شدن CORS
3. آدرس نادرست یا ۴۰۴

### ارتباطش با LiteSpeed

خط بالایی `[LiteSpeed] Start Lazy Load` نشان می‌دهد اسکریپت
lazy-load لایت‌اسپید فعال است. این اسکریپت برای بارگذاری تنبل
تصاویر، درخواست‌هایی به سرور می‌فرستد. وقتی سرور کند یا خاموش
باشد، همین درخواست‌ها با `Failed to fetch` شکست می‌خورند.

**نکتهٔ مهم:** خودِ lazy-load مقصر نیست — قربانی است. اگر سرور
سالم بود، این خطا رخ نمی‌داد.

## آیا روی سئو اثر دارد؟

**خبر خوب:** در همان تصویر، Search Console می‌گوید:

> ✅ URL is available to Google  
> ✅ Page can be indexed

یعنی گوگل توانست صفحه را ببیند و ایندکس کند. خطای جاوااسکریپت
مانع ایندکس نشده.

**خبر بد:** اگر خطای ۵۲۲ ادامه‌دار باشد، گوگل در خزش‌های بعدی به
صفحه دسترسی نخواهد داشت و این **جدی است**. سایتی که مکرر
در دسترس نباشد، رتبه‌اش افت می‌کند.

## اقدامات، به ترتیب اولویت

### ۱. بررسی سلامت سرور — فوری 🔴

خطای ۵۲۲ معمولاً یکی از این‌هاست:

| علت | راه بررسی |
|---|---|
| مصرف بیش از حد CPU یا RAM | پنل هاست ← Resource Usage |
| کندی پایگاه داده | بررسی کوئری‌های کند |
| محدودیت تعداد پردازش (`entry processes`) | پنل هاست |
| فایروال سرور که IP کلادفلر را بسته | تنظیمات فایروال |

**اگر هاست اشتراکی دارید:** با پشتیبانی تماس بگیرید و بگویید
«خطای 522 از سمت کلادفلر می‌گیرم، لطفاً منابع سرور را بررسی کنید».

### ۲. تشخیص دقیق منبع fetch

پس از بالا آمدن سایت، در مرورگر:

1. `F12` ← تب **Network**
2. صفحه را با `Ctrl+Shift+R` تازه کنید
3. فیلتر روی **Fetch/XHR**
4. دنبال ردیف قرمز بگردید

آن ردیف قرمز، آدرس دقیق درخواست شکست‌خورده را نشان می‌دهد.
معمولاً یکی از این‌هاست:

- `/wp-json/...` — REST API وردپرس
- `/wp-admin/admin-ajax.php` — درخواست ای‌جکس افزونه‌ها
- `/wp-content/plugins/litespeed-cache/...` — خود لایت‌اسپید

### ۳. اگر مشکل از lazy-load بود

**LiteSpeed Cache ← Page Optimization ← Media Settings**

گزینه‌های زیر را موقتاً خاموش کنید و تست کنید:

- `Lazy Load Images`
- `Lazy Load Iframes`
- `Generate LQIP` (این یکی به سرور بیرونی وصل می‌شود و اگر کند
  باشد همین خطا را می‌سازد)

**احتمال بالا:** گزینهٔ **LQIP Cloud Generator** به سرویس بیرونی
لایت‌اسپید درخواست می‌فرستد. اگر آن سرویس در دسترس نباشد یا
فایروال ایران مسدودش کند، دقیقاً `Failed to fetch` می‌دهید.

### ۴. اگر مشکل از REST API بود

بررسی کنید `/wp-json/` باز است:

```
https://qpedia.ir/wp-json/wp/v2/posts
```

اگر ۴۰۳ یا ۴۰۱ داد، افزونهٔ امنیتی REST API را بسته. بسیاری از
قابلیت‌های وردپرس به آن نیاز دارند.

## جمع‌بندی

| مورد | وضعیت |
|---|:--:|
| ایندکس شدن صفحه | ✅ مشکلی ندارد |
| خطای جاوااسکریپت | ⚠️ نشانه است، نه علت |
| **دسترسی سرور** | 🔴 **مشکل اصلی** |

**اولویت اول: سرور را سالم کنید.** خطای ۵۲۲ خیلی مهم‌تر از آن
پیام کنسول است. به احتمال زیاد وقتی سرور پایدار شد، خطای
`Failed to fetch` هم خودبه‌خود برطرف می‌شود.
